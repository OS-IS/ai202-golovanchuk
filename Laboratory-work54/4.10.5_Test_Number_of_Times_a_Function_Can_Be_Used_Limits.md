# 4.10.5 Тестування обмеження кількості використань функції

### Короткий зміст
Багато проблем, які вирішують додатки, вимагають обмеження кількості разів використання функції або виконання дії. Додатки повинні бути «достатньо розумними», щоб не дозволяти користувачеві перевищувати ліміт використання цих функцій, оскільки в багатьох випадках кожного разу, коли функція використовується, користувач може отримати певну вигоду, яку необхідно враховувати для належної компенсації власнику. Наприклад: сайт електронної комерції може дозволяти користувачам застосовувати знижку лише один раз за транзакцію, або деякі додатки можуть мати план підписки та дозволяти користувачам завантажувати лише три повні документи щомісяця.

Вразливості, пов’язані з тестуванням на обмеження функцій, є специфічними для кожного додатка, і необхідно створювати випадки зловживання, які прагнуть використовувати частини додатка/функцій/або дій більше, ніж дозволено.

Зловмисники можуть обійти бізнес-логіку та виконати функцію більше разів, ніж «дозволено», використовуючи додаток для особистої вигоди.

### Приклад
Припустимо, що сайт електронної комерції дозволяє користувачам скористатися будь-якою з багатьох знижок на загальну покупку, а потім перейти до оформлення замовлення та оформлення тендеру. Що відбувається, якщо зловмисник повертається на сторінку знижок після отримання та застосування однієї «допустимої» знижки? Чи може він скористатися іншою знижкою? Чи може він скористатися тією ж знижкою кілька разів?

### Цілі тестування
Визначити функції, які повинні встановлювати обмеження на кількість викликів.
Оцінити, чи встановлено логічне обмеження для функцій і чи воно належним чином перевірено.
Як тестувати
Переглянути документацію проекту та використовувати дослідницьке тестування, шукаючи функції або можливості в додатку чи системі, які не слід виконувати більше одного разу або певної кількості разів протягом робочого процесу бізнес-логіки.
Для кожної знайденої функції та можливості, які слід виконувати лише один раз або певну кількість разів протягом робочого процесу бізнес-логіки, розробити випадки зловживання/неправильного використання, які можуть дозволити користувачеві виконувати їх більше дозволеної кількості разів. Наприклад, чи може користувач переміщатися між сторінками кілька разів, виконуючи функцію, яка повинна виконуватися лише один раз? Або чи може користувач завантажувати та розвантажувати кошики для покупок, дозволяючи отримувати додаткові знижки.

### Виправлення
- Усі обмеження на кількість використань функцій повинні перевірятися **на стороні сервера**, а не на клієнті.  
- Для купонів або кодів знижок: після їх застосування слід відзначати використання у базі даних, щоб уникнути повторного застосування.  
- Для лімітів завантажень: вести підрахунок на бекенді для кожного користувача/акаунту й відхиляти спроби перевищення ліміту.  
- Для транзакцій із кількісними обмеженнями: забезпечити, щоб обмеження не можна було обійти за допомогою повторних запитів чи відкриття нових сесій.
